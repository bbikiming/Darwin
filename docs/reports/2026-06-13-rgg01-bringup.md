## 0. 결론

**조종 성립.** ARM(A) → 왼스틱 이동 · LT/RT 아날로그 회전 · 우스틱 헤드 레이트 제어 ·
B E-STOP → Y 소프트 복구(토크 램프) → 즉시 재보행 — 전 플로우 실기 입회 확인.

단, 시작 시점 코드는 **치명 결함 1건(P1급)을 품고 있었다**: E-STOP 복구가 관절 enable 을
복원하지 않아, **estop 이력이 있는 세션에서 명령·ACK 는 전부 정상인데 물리 반응만 0**
(§3 실기 F9). 호스트 141 checks 가 못 잡은 이유 = 관절 enable 은 Robot:: 결합층이라
호스트 테스트 범위 밖. "ACK enabled=1 ≠ 서보 기록"이 이 브링업의 핵심 교훈.

게이트 ①·②·④ 통과(②는 측정 정의 보정 — §2), ③·⑤·⑥은 부분/미완(§5 잔여). 사용자
피드백으로 조작계 리디자인(F10/F10b — 콕핏 패리티 의도적 이탈)과 레이턴시 개선(F11)을
같은 세션에서 적용·검증했다.

## 2. 입회 게이트 결과

### ① ABS_X 부호 — **통과, GP_SIGN_SIDE 수정 불필요**

- 왼스틱 우 → ACK `y=-21.4` 실측(라운드4, gp14609~) — 예상(−=우횡)과 일치.
  `GP_SIGN_SIDE = -1.0` 확정(헤더 주석 "표준 가정"→"실측 확정" 갱신).
- D-pad 4방 실측(HAT0X 좌**−1**/우+1·HAT0Y 상**−1**/하+1 — H0 미관측이던 −1 포함),
  스틱클릭 317/318 press/release 실측. 미배선 유지 — 기록만.
- ABS_X 풀레인지 −32768..+32249 관측.

### ② E-STOP — **통과(측정 정의 보정)**

- **B 누름(evdev) → estop flag 생성(mtime): ≤2ms ×3회** (74859.945/74870.484/74879.326 —
  flag mtime 이 외부 evdev 로거 타임스탬프보다 1~1.4ms 선행 = 데모 reader 스레드가
  로거보다 빨랐다). flag 생성은 `TriggerEstopImmediate`(Walking::Stop + SetEnableBody(false)
  + flag) 와 동일 호출 내 — **≤20ms 사양 충족**.
- 보행 중 발화 검증: 3회 모두 x=32~37mm 주행 라인 한복판에서 B → ACK 스트림 즉시 동결
  (flag ON 구간 ACK 0줄 — 게이트 구조 검증) + 입회 물리 정지 확인.
- **한계 고지**: 서보 정지 완료까지의 물리 타임스탬프는 미계측(계측 수단 없음 — Stop 호출
  지연만 확정). 종전 "1-2ms PASS" 표현은 flag 생성 지연으로 정정.
- 복구 플로우: Y = estop flag 해제 + ARM(연속 검증 — F9 이후 관절 재enable 포함, §3).

### ③ 단절 매트릭스 — **부분(절전만 실측)**

- **절전(graceful)**: 세션 중 자연 발생 다수 — USB 재enumerate(input9→10→11, Receiver
  Update 이중 enumerate 패턴), 파일럿 자동 재획득, gp cmd 스트림 연속(시퀀스 리셋 없음).
- 전원 OFF·거리 이탈·배터리 탈락·동글 뽑기: **미실측** (시간 제약 — 잔여 §5).

### ④ 재전원 → 자동 재획득 → 재 ARM — **통과**

- 재enumerate 후 ~1.3s 재획득(노드명 event8 재사용 — 이름+VID/PID 재스캔 경로 정상).
- **재 ARM 필수 흐름의 실증**: 라운드5 — A 없이 LB+스틱(풀스케일) → 전부 enabled=0
  (이동 잠금 정상 동작). A 1회로 즉시 무장 → 주행.

### ⑤ 10분 CPU·loop_ms — **부분**

- 카메라 펌프(8080) 동시 가동 상태에서 loop_ms 실측: 유휴 ~101ms · 활동 ~40ms ·
  보행 ~20-34ms(ACK 간격) — O1 설계 주기와 정합. load avg ~0.8-0.9.
- 10분 연속 조종 세션의 분포 수집은 미완(잔여).

### ⑥ ③티어 침묵 임계 — **초기값 유지(실기 분포 미실측)**

- `GP_SILENCE_SLEW_MS = 1500` 유지. 호스트 시뮬로 오발 시나리오(스틱 레일 고정 →
  이벤트 0 → 1.5s 후 완만 정지) 재확인 — 실기에서도 동일 거동 예상되어 사용자에게
  "스틱을 미세하게 움직이라"로 안내. 정속 직진 실분포 수집은 잔여.

## 3. 발견 결함과 수정 (실기 F9 — P1급)

### 근본 원인: E-STOP 복구가 관절 enable 을 복원하지 않음

증상(라운드6): Y→A→LB+풀스틱 전부 evdev 도달, ACK enabled=1 92줄(x→37mm), **물리 반응 0**.

원인 사슬(5-에이전트 교차 조사로 확정 — 코드+로그 전 링크 검증):
1. B → `TriggerEstopImmediate` → `Walking::Stop` + `m_Joint.SetEnableBody(false)` — 전 관절 enable=false
2. Y → flag 해제 → 재무장 분기 — **재enable 호출 전무**. 주석 "body torque 는 다음
   Start() 가 복구"는 **허위**: 실기 펌웨어 `Walking::Start()` 는 플래그 2개만 세팅
   (Walking.cpp:340-344), `MotionManager::Process` 는 `GetEnable(id)==true` 인 관절만
   서보에 기록(MotionManager.cpp:273)
3. → 명령 경로(무장·중재·ApplyCommandLine·Walking::Start·ACK)는 완전 정상, 서보 기록 0건
4. estop 이력 없는 라운드(1·4)만 움직였던 패턴과 정확히 일치

수정(F9, `WalkLabBrokerage.cpp` 재무장 분기):
- getup 반납과 동일 패턴으로 `SetEnableHeadOnly(true,true)` + `SetEnableBodyWithoutHead(true,true)`
- **한 쌍 필수**: stale enabled=1 cmd 파일 재적용 가드(현재 stat 캡처 — getup codex HIGH fix
  패턴). 종전 `memset(last_stat,0)` 강제 재처리는 관절이 살아난 뒤엔 무의도 즉시 재보행이 됨
- 실기 검증: B→Y→A→스틱 → **즉시 재보행** 입회 확인

### 동반 수정(F9 — 잠재 안전 결함, 호스트 테스트 +9)

- **B E-STOP 스테일 면역**: rising 검사(`!ButtonState`)가 release 유실(링 오버플로) 시
  B 를 영구 침묵시킬 수 있었다 → B 는 value==1 이면 무조건 발화(멱등이라 중복 무해)
- **SYN_DROPPED 처리**: 커널 링 오버플로 통지 시 디코더 리셋(押下 고착 차단 — 정지 측 편향)
- **관측성**: `setvbuf(stdout, _IOLBF)` + `ClearEstopFlag` unlink 결과 로그 — 종전엔
  안전 이벤트 로그가 수 시간 버퍼에 갇혀 사후 분석 불능이었다(라운드6 분석 지연의 주범)

### 세션 중 "거짓으로 판명된" 중간 판정 (정직 기록)

- "라운드6 ACK 전부 enabled=0" — **오독**(실제 en=1 92줄). "라운드5 스틱 살짝(-288)" —
  **축 오독**(실제 LY 풀스케일). 데드존 가설 폐기.
- "E-STOP 1-2ms 통과" — flag 생성 지연만 측정한 것(§2 ② 보정).
- estop watcher "OFF 기록 없음" — watcher 사망 구간의 스테일 관측.

## 4. 조작계 리디자인 (실기 F10·F10b — 사용자 피드백) + 레이턴시 (F11)

콕핏 RG G01 프리셋 1:1 패리티에서 **의도적 이탈** (ssh-parity-contract 매핑 표 후속 개정 필요):

| 컨트롤 | 종전(H1) | 현재(F10b) |
|---|---|---|
| 왼스틱 | 이동(전후/횡) | 동일 |
| 우스틱 X | 턴 | **헤드 팬 — 레이트 제어**(곡선 1.7, 최고 150°/s) |
| 우스틱 Y | 헤드 틸트(절대) | **헤드 틸트 — 레이트 제어**(곡선 1.7, 최고 85°/s) |
| LT/RT | 헤드 팬(차분) | **좌/우회전 — 아날로그 비례**(데드존 0.02, 저압 부스트 ^0.65) |
| LB | 데드맨(기본 ON) | **해제**(`GP_DEADMAN_REQUIRED=false` — 이동 게이트는 ARM 단일) |
| RB / A / B / X / Y | 터보 / ARM / E-STOP / 볼트랙 / 복구 | 동일 |

- 헤드 레이트: dt 적분(상한 200ms) + ±70°/±35° 클램프, 놓으면 각 유지. 저속 구간은
  곡선 상향(1.35→1.7)으로 종전 ±25% 내 유지(호스트 검증), 풀스틱만 90→150·50→85°/s.
- 데드맨 해제의 안전 영향: ①티어(LB release 합성)는 무효화 — 단절 보호는 ②티어
  (ENODEV, release +~1ms 후속·공통원인)·③티어(침묵 1.5s)가 소화. E-STOP·ARM 불변.
- **Y 복구 소프트 토크(F10)**: Torque Limit 램프 300→600→900→1023(150ms 간격, ~0.6s) —
  복구 순간 관절 스냅 제거. 입회 확인.
- **레이턴시(F11)**: 유휴 supervisor 루프 100ms → 패드 신선(≤1s) 시 20ms(첫 입력 소비
  지연 평균 50→10ms) · estop hold 폴 100→20ms(복구 감지 평균 50→10ms). 패드 유휴 시
  100ms 유지(CPU 불변).

검증: 호스트 `test_gamepad` **163 checks 0 fail**(141→163) · `test_transport` **170 checks
0 fail** · 실기 입회 — 이동/회전/헤드/E-STOP/복구/재보행 전 플로우 + 저압 트리거·헤드
속도 튜닝 확인.
