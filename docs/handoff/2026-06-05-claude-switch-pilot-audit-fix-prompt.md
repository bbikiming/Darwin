## 5. Required Fixes

### P1. Safety blocker: stale motion can be sent after Stop/E-stop state change

Files:

```text
tools/switch-pilot/src/darwin_switch_agent/main.py
tools/switch-pilot/tests/
```

Evidence:

- `main.py` computes `command = gate_motion(raw_command, armed=armed, estopped=estopped)` before actions and edge handling around lines 106-110.
- The bus action loop can set `estopped=True` / `armed=False` after that around lines 124-156.
- Mac relay edge handling can set E-stop after that around lines 205-217, but the send path still uses the old `command` around lines 218-222.
- SSH edge handling can set E-stop after that around lines 256-276, but line comparison and send still use the old `command` around lines 282-289.
- `bus.publish(...)` currently happens before mode-specific physical edge handling, so the UI can also publish stale command state around lines 175-185.

Why this matters:

- A robot-control loop must treat Stop/E-stop as a last-line safety gate.
- Current ordering can issue E-stop or Stop and then still send the prior moving command in the same tick if the send interval is due.
- This is the highest-priority issue. Do not install on real robot before fixing it.

Required implementation:

1. Keep `raw_command = mapper.map(controller)` as the input-derived command.
2. Use a preliminary gated command only if `SafetyState.update(...)` needs a command for edge history. Currently `SafetyState.was_moving` is set but not used, so this may be simplified.
3. Drain cockpit/bus actions and update `armed` / `estopped`.
4. Process mode-specific physical edges and update `armed` / `estopped`.
5. Track a per-tick `force_stop_this_tick` boolean for `stop`, `deadman_released`, and any screen Stop action. Stop does not necessarily have to latch E-stop, but it must suppress nonzero motion for the current tick.
6. Only after actions and edges are settled, compute the final command:

```python
command = gate_motion(raw_command, armed=armed, estopped=estopped)
if force_stop_this_tick:
    command = gate_motion(raw_command, armed=False, estopped=True)  # or a small zero_command helper
```

Prefer a clear helper instead of abusing `estopped=True` semantically:

```python
def zero_motion(command: MotionCommand) -> MotionCommand:
    return replace(command, enabled=False, stride_mm=0.0, turn_deg=0.0,
                   head_pan_deg=0.0, head_tilt_deg=0.0)
```

Then:

```python
command = gate_motion(raw_command, armed=armed, estopped=estopped)
if force_stop_this_tick:
    command = zero_motion(command)
```

7. Publish `bus.publish(...)` after the final command is computed, so the UI sees the same command that could be sent.
8. Use the final command for heartbeat labels, Mac relay `walk/head`, robot UDP send, and SSH line/send.
9. On E-stop, also clear `last_moving` and avoid sending Mac `walk/head` in that tick.
10. On SSH E-stop, touching `/tmp/df-walklab-estop` is authoritative. Do not send a nonzero SSH command line after it in the same tick.

Testing requirement:

Add targeted tests. Do not rely only on `test_gate.py`; it tests the helper but not the loop ordering.

Acceptable approach:

- Extract a small pure helper from `main.py`, for example:

```python
@dataclass(frozen=True)
class SafetySettlement:
    armed: bool
    estopped: bool
    force_stop_this_tick: bool

def settle_safety_state(armed: bool, estopped: bool, actions: list[ControlAction], edges: SafetyEdges) -> SafetySettlement:
    ...
```

Then test it directly.

Minimum tests:

- Moving raw command + cockpit `estop` action in same tick -> final command disabled/zero.
- Moving raw command + physical `estop_pressed` edge in same tick -> final command disabled/zero.
- Moving raw command + cockpit `stop` action in same tick -> explicit stop is requested and final command zero for that tick.
- Moving raw command + `deadman_released` edge -> final command zero.
- `arm` or `recover` after E-stop clears `estopped` only through the intended branch.
- `bus.publish` uses final zeroed command when E-stop/Stop occurs.

If you choose not to extract a helper, create fake clients/readers around one loop iteration instead. But avoid fragile tests around the infinite loop; a pure helper is cleaner.

Acceptance criteria:

- A Stop/E-stop event cannot be followed by a nonzero Mac relay, SSH, or UDP command in the same iteration.
- Existing tests still pass.
- New tests fail on the old ordering and pass after the fix.
