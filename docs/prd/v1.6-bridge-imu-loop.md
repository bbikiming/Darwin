## 0. 한 줄 결론

Mac 측 5Hz polling + Swift ComplementaryFilter 는 **정적 추정보다 약간 안정** 한 수준.
**진짜 동적 자세 추적** (걷기 중 자세, fall detection, head pan-during-walk 보정) 을 위해선
**robot-side 100Hz IMU loop + ComplementaryFilter state** 가 필요. 본 PRD 가 그 구조를 정의.

## 1. v1.5 의 한계 (재확인)

| 항목 | v1.5 상태 | 한계 |
|---|---|---|
| IMU read | Mac polling 5Hz | dt=200ms — gyro 적분 1초 안에 10° drift 가능 |
| ComplementaryFilter | Swift, alpha=0.71 (tau=0.5s) | settling ~2.5 cycle. 빠른 동작 추적 불가 |
| fall detection | accel-only tilt 60° 임계 추정 | ROBOTIS FB_ACCEL 30 sample 평균 = ~300ms latency. 우리 5Hz 만으로 충분 X |
| Mac head tracking PID | 4Hz camera detection | 진동 위험. v1.5 의 PD + deadband + clamp 도 한계 |

**근본 원인**: USB serial bus (1Mbps half-duplex) + forge-bridge socat 양방향 latency ~5-10ms per packet. Mac → TCP 5530 → bridge → USB → CM-740 → response 의 round-trip 이 5Hz 이상 어려움.

## 3. 구조 옵션 분석

### 옵션 A — `forge-bridge` 의 Rust 재작성 ⭐ 추천

기존: `socat tcp-l:5530,reuseaddr,fork,nodelay open:/dev/ttyUSB0`
변경: `forge-bridge` 가 Rust binary — socat 역할 + IMU loop 통합.

**구조**:
```
forge-bridge (Rust daemon)
├── TCP 5530 server (기존 socat 호환 — Mac 의 일반 dynamixel)
│   ↓ proxy
├── /dev/ttyUSB0 access (single owner)
│   ↑ ↓
└── IMU loop thread (100Hz)
    ├── read register 38..49 every 10ms
    ├── ComplementaryFilter state (alpha = 0.98)
    ├── fall detection (FB_ACCEL 30-sample moving avg)
    └── shared state (mutex) — TCP 5531 server 가 노출
        TCP 5531 binary frame: roll/pitch/fall_state/sample_count (4Hz push)
```

**Mac 변경**:
- `ForgeCore/Bus.swift` 에 `connectFiltered(host:port:5531)` 추가
- `ConnectionStore` 가 5530 (dynamixel) + 5531 (filtered IMU) 두 endpoint
- 5531 는 1Hz push receive — polling 안 함

**장점**:
- ROBOTIS 공식 LinuxCM730 pattern 그대로
- USB bus single owner — 충돌 없음
- 100Hz IMU + 100Hz dynamixel write 동시 가능 (~10% bus utilization)

**단점**:
- 큰 작업: socat 대체 Rust binary 작성 + cross-compile (DARwIn-OP Ubuntu 12.04/14.04 i386 또는 armhf?)
- 기존 master setup 의 init.d/forge-bridge 변경

### 옵션 B — 별도 Python script (v1.5 호환)

`/usr/local/bin/df-imu-loop.py` — pyserial 로 /dev/ttyUSB0 read.

**한계**:
- forge-bridge socat 와 USB bus 충돌. **양립 불가**.
- forge-bridge 가 꺼지면 Mac 모터 송출 불가. Trade-off.

→ **별도 시나리오: "IMU only 모드"** — 사용자가 head tracking + IMU 정밀도 우선이고 모터 송출 비활성 모드. 옵션 C 위에 추가.

### 옵션 C — forge-bridge 가 IMU register cache + 5530 multiplex

기존 socat 보존하되, IMU register read 만 가로채서 cache + filter:
```
incoming packet (Mac → bridge)
  ├── 일반 dynamixel → /dev/ttyUSB0 그대로 forward
  └── ID 200 register 38-49 read → 가로채서 cache 응답 (100Hz 로 별도 update)
```

**장점**:
- 기존 socat client/protocol 그대로 — Mac 변경 최소
- IMU read 가 빠른 응답 (cache 에서) → Mac polling 빈도 그대로 가능

**단점**:
- protocol 분기 복잡 (dynamixel packet 파싱 — checksum 까지 검증해야)
- 디버깅 어려움

### 결정

**옵션 A 권고**. Rust binary 재작성 한 번 하면 v1.6 ~ v2 모두 사용 가능. Cross-compile 은 기존 forge-core 와 같은 toolchain.

## 4. forge-bridge v1.6 명세

### 4.1 명령행 인터페이스

```
forge-bridge [OPTIONS]
  --usb-port <PATH>           /dev/ttyUSB0 (default)
  --baud <RATE>               1000000 (default)
  --listen-dxl <ADDR>         0.0.0.0:5530 (Dynamixel passthrough)
  --listen-telemetry <ADDR>   0.0.0.0:5531 (filtered IMU)
  --imu-rate <HZ>             100 (default, 10~200 허용)
  --filter-tau <SEC>          0.5 (default)
  --fall-threshold-low <RAW>  390 (FB_ACCEL Z-axis raw 임계)
  --fall-threshold-high <RAW> 580
  --log-level <LEVEL>         info
```

### 4.2 5531 telemetry protocol (binary frame)

매 250ms (4Hz) push:

```
[ magic 4B "DFTM" ]
[ version 1B = 1 ]
[ frame_type 1B = 0 (IMU snapshot) ]
[ timestamp_ms 8B (uint64 big-endian, since daemon start) ]
[ roll_deg 4B (float32 big-endian) ]
[ pitch_deg 4B (float32 big-endian) ]
[ gyro_x_dps 4B (float32) ]
[ gyro_y_dps 4B (float32) ]
[ gyro_z_dps 4B (float32) ]
[ accel_x_g 4B (float32) ]
[ accel_y_g 4B (float32) ]
[ accel_z_g 4B (float32) ]
[ fall_state 1B (0=upright, 1=forward, 2=backward) ]
[ sample_count 4B (uint32) ]
[ crc32 4B ]
= 50 bytes per frame
```

### 4.3 IMU loop pseudocode

```rust
loop {
    let t0 = Instant::now();
    let raw = read_imu_register()?;   // 12 byte burst
    let dt = last_loop.elapsed();

    filter.update(raw, dt);   // ComplementaryFilter (alpha = tau / (tau + dt))

    // ROBOTIS FB_ACCEL moving average for fall detection.
    fb_z_window.push(raw.accel_z);
    if fb_z_window.len() > 30 { fb_z_window.pop_front(); }
    let avg = fb_z_window.iter().sum::<i16>() / fb_z_window.len() as i16;

    let fall = if avg < 390 { FallState::Forward }
               else if avg > 580 { FallState::Backward }
               else { FallState::Upright };

    shared_state.lock().update(filter.roll, filter.pitch, raw, fall);

    let elapsed = t0.elapsed();
    let target = Duration::from_millis(10);   // 100Hz.
    if elapsed < target {
        thread::sleep(target - elapsed);
    }
}
```

### 4.4 Mac 측 변경

```swift
extension Bus {
    /// 5531 filtered IMU stream — push 받음. binary parsing.
    public init(filteredImuHost: String,
                imuPort: UInt16 = 5531) throws { ... }
}

// ConnectionStore 에 추가:
@Published public private(set) var filteredImu: FilteredImuSnapshot?
public struct FilteredImuSnapshot {
    public let rollDeg: Double
    public let pitchDeg: Double
    public let fallState: FallState
    public let gyroDps: SIMD3<Double>
    public let accelG: SIMD3<Double>
    public let sampleCount: UInt32
    public let timestamp: Date
}
```

PilotHudStrip 의 imuBlock 자동 분기:
- filteredImu != nil → "IMU (100Hz CF)" 라벨 + filtered 값
- nil → 기존 Mac CF fallback
- 둘 다 없으면 "IMU 불가"

## 5. 자동복구 (fall detection 활성)

v1.5 에서 비활성된 `autoRecovery` flag 가 v1.6 에서 활성 가능:
- `filteredImu.fallState == .forward` → `channel.sendMotion(slot: 10, confirmRisk: true)` (FORWARD GETUP)
- `filteredImu.fallState == .backward` → `channel.sendMotion(slot: 11, ...)` (BACKWARD GETUP)
- 디바운싱: 3 연속 frame (~750ms) 동안 같은 fall state 유지 시만 트리거 (false positive 방지)

## 6. cross-compile 작업

DARwIn-OP 의 OS 는 보통 Ubuntu 12.04 / 14.04 i686 또는 armhf. Rust target:
- `i686-unknown-linux-gnu` (Atom Z530 CPU)
- 또는 `armv7-unknown-linux-gnueabihf`

`forge-bridge` 의 dependency:
- `std::os::unix::serial` (또는 nix crate) — termios 직접 설정
- `std::net::TcpListener`
- `crc32fast` 의존성

Cross-compile + statically linked binary → `df-forge-bridge` 라는 단일 실행 파일.
master setup 의 init.d 가 socat 대신 이 binary 호출.

## 9. 위험 / 미해결

1. **cross-compile toolchain**: DARwIn-OP 의 i686 / armhf gcc 가 robot 측에서 빌드 가능한지 검증 필요. cross 가 안 되면 robot 측 빌드 helper (rustup target add) 필요.
2. **forge-bridge 의 USB bus contention**: 100Hz IMU loop + Mac SYNC_WRITE 동시 시 latency spike 가능. profile 후 IMU loop 빈도 조정.
3. **ROBOTIS demo 와 양립**: demo 가 USB 점유하면 forge-bridge 죽음 → IMU loop 도 중단. 이건 의도된 동작 — demo 자체가 자체 IMU loop 보유.
4. **Phase E 의 Mac CF 가 v1.6 에서 무용해짐** — 코드 정리: filteredImu 있으면 Mac CF skip + UI 분기.
