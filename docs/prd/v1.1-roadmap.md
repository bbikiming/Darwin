# DarwinForge v1.1 Roadmap

**기준**: v1.0.0 (`eddb5b4`, 2026-05-15) 머지 + Codex 4-pass audit 완료 후 잔여
후순위 항목 정리.

**원칙**: v1.0 에서 명시한 안전 분리 + ROBOTIS 공식 source 1:1 정합을 유지하면서,
**실 로봇 HIL 검증을 마치고** 다음 capability 를 추가한다.

## P0 — `signal-hook` Ctrl+C emergency stop

### 현재 상태

`forge-cli/src/motion_play.rs:341-368` 의 `setup_ctrlc_handler()` 는 placeholder
(`Ok(())` 반환만). Module doc 에 "사용자 안내: 위급 시 USB 케이블 분리 또는 robot
후면 reset" 명시.

### 변경 사항

1. `forge-cli/Cargo.toml` 에 `signal-hook = "0.3"` 추가
2. `motion_play.rs` 의 `setup_ctrlc_handler()` 실제 구현:
   ```rust
   use signal_hook::consts::SIGINT;
   use signal_hook::iterator::Signals;
   use std::sync::atomic::{AtomicBool, Ordering};

   static EMERGENCY_STOP: AtomicBool = AtomicBool::new(false);

   fn setup_ctrlc_handler() -> Result<(), Box<dyn std::error::Error>> {
       let mut signals = Signals::new([SIGINT])?;
       std::thread::spawn(move || {
           for _ in signals.forever() {
               EMERGENCY_STOP.store(true, Ordering::SeqCst);
               eprintln!("\n🛑 SIGINT — 다음 step 직전 emergency stop");
           }
       });
       Ok(())
   }
   ```
3. step loop 직전 check:
   ```rust
   if EMERGENCY_STOP.load(Ordering::SeqCst) {
       // torque OFF + bus close
       jc.set_torque_many(&all_joints, false)?;
       eprintln!("✓ 토크 OFF + bus 종료");
       break;
   }
   ```
4. 회귀 테스트 — placeholder 가 다시 들어오는 회귀 방지

### 영향

- `forge motion play --engage` 중 Ctrl+C 누르면 **모터 즉시 풀림** (낙상 예방)
- placeholder doc 제거 + "Ctrl+C 안전 정지 보장" 약속 추가

## P1 — raw motion chain replay (motion_play trapezoid)

### 현재 한계

`motion_play.rs` 는 step 마다 `set_positions_many` + `sleep(playMs)` 만 한다.
ROBOTIS `Action.cpp:271-683` 의 **PRE/MAIN/POST/PAUSE section + speed/accel/slope
기반 trapezoid 보간**을 재현 X.

→ 짧은 play_time (예: page 12 step 3 의 72 ms) 에서 jerk 발생 가능.
→ slope (compliance) 적용 안 됨.

### 변경 사항

1. `forge-core/src/motion/replay.rs` (신규) — `ActionReplay` struct:
   - `PRE_SECTION` / `MAIN_SECTION` / `POST_SECTION` / `PAUSE_SECTION` enum
   - `wUnitTimeNum` 계산 (Action.cpp:412-447)
   - speed 보간 (Action.cpp:367-403)
   - 8 ms tick 단위 (TICK_MS=8)
2. `motion_play.rs` 의 step loop 를 `ActionReplay::tick()` 으로 대체
3. forge-ffi 의 `fc_motion_play_chain(slot, max_pages, ...)` 추가
4. 회귀 테스트:
   - PRE→MAIN→POST 순서 + 시간 분배 검증 (Action.cpp:419-446 정량)
   - slope = 0x55 에서 P-gain 적용 (`m_Joint.SetSlope(...)` 등가)

### 산출물

`docs/motion-format/06-action-replay-engine.md` — Action.cpp 의 timing 수식
정리 + 우리 구현 매핑 표.

## P1 — ROBOTIS Walking.cpp 8 ms realtime loop

### 현재 한계

`WalkMotionLibrary` 는 **6-phase sparse keyframe approximation**. ROBOTIS
`Walking.cpp:495-650` 의 실 walking 은 8 ms 마다 phase update + IK + gyro
balance + P/I/D gain.

| 항목 | 공식 Walking.cpp | 현재 v1.0 (sparse) |
|---|---|---|
| sample rate | 8 ms (125 Hz) | 6 phase / period (≈10 Hz) |
| IMU closed loop | gyro_x/y P+I+D | ✗ |
| 분석적 IK | ✓ | 단순화된 X/Y/Z swap |

### 변경 사항

1. `forge-core/src/walk/realtime.rs` (신규) — `WalkingEngine` struct:
   - Walking.cpp 의 `update_param` 함수 포팅 (line 270-470)
   - IK: `compute_ik(x, y, z, a, ...)` (Walking.cpp:475-560)
   - IMU 입력 → gyro balance correction (Walking.cpp:602-650)
2. forge-ffi `fc_walking_start(...)` + `fc_walking_tick_with_imu(...)`
3. Mac UI: `runRealtimeWalk` Task 가 8 ms tick 으로 fc_walking_tick 호출 →
   `set_positions_many` 송출
4. WalkLab UI: "공식 보행 엔진 사용" toggle (advanced 모드 안)

### 검증

- ROBOTIS demo 의 SOCCER 모드와 같은 보행 패턴 ↔ 우리 realtime engine 비교
- 같은 stride / period 입력 → 같은 발 trajectory 출력 (within 5 mm)

### 위험

- IK 분석적 풀이 복잡 — 단위 테스트 충분히 작성 필요
- 8 ms tick 의 Mac → robot 통신 latency (USB 환경에선 ~1-2 ms, TCP 5530 forge-bridge
  환경에선 5-10 ms 가능) → 실시간성 영향 분석 필요

## P2 — Pilot HSV 튜닝 — 색 sampler

### 현재 상태

⌘8 → 카메라 HUD → 튜닝 시트 → 6 슬라이더 수동 조정. 사용자가 화면 색을 보고
대략 hue/sat/val 추정해야.

### 변경 사항

- 카메라 frame 위에 **클릭 = pixel 색 sampler** — clicked pixel 의 (h, s, v)
  값 → 슬라이더 자동 set
- 다른 클릭 = average — 영역 평균 hue
- "이 색 추가" 버튼 — 가장 가까운 tag (orange/red/yellow/blue) 의 슬라이더 갱신

### 검증

- 단위 테스트: pixel 클릭 → 슬라이더 값 매핑
