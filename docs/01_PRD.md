# 01 — PRD: DarwinForge 텔레옵·3D 업그레이드 프로그램

> 프로그램 단위 PRD. 기능별 상세 PRD 는 `docs/prd/`, 설계는 `docs/design/` 참조.
> 작성 2026-06-12 · 상태: **승인됨(구현 진행 중)** · 하네스: 01~06 문서가 본 프로그램의
> 요구→계획→합격기준→리뷰→결과 체인을 구성한다.

## 1. 배경 / 문제

ROBOTIS OP2 두 대를 제어하는 DarwinForge 는 기능적으로 완성 단계이나, 2026-06 전수 조사
(설계 문서 6종)에서 세 가지 구조적 한계가 확인됐다:

1. **조종 반응성**: 온보드(SSH) 경로 실효 4–8Hz·입력→보행 반영 0.7–1.0s, E-STOP 로봇 측
   바닥 100ms — 원인은 알고리즘이 아니라 전송·폴링·이중 스무딩의 합 (`docs/design/walklab-onboard-teleop-upgrade.md` §2).
2. **조종 안정성·안전**: 밸런스 토큰 사문화, FSR 미사용, 로봇 측 최종 클램프(거버너) 부재
   — Switch 가 stride 50mm 를 무방비 통과.
3. **시각화 정보 밀도**: 3D 뷰가 Blinn-Phong 단색이었고(W0·W1 에서 PBR/IBL 해소) CoM·
   지지다각형·FSR 등 로봇공학 오버레이 부재.

추가로 사용자 결정(2026-06-11): **RG G01 2.4G 동글을 로봇 USB 에 직결**하는 최저지연
조종 경로를 신설한다(유선 USB-C 는 폴백).

## 2. 목표 (사용자 가치)

| # | 목표 | 측정 |
|---|---|---|
| G1 | "빠릿한" 원격 조종 — 입력이 다음 걸음에 반영 | 온보드 명령 실효 ≥20Hz, 입력→래치 ≤ 반주기+α |
| G2 | 어떤 클라이언트에서도 안전 — 로봇이 최종 안전판 소유 | 거버너 클램프 + E-STOP 전 소스 상시 |
| G3 | E-STOP 을 "즉시"로 — 전 경로 | bus ≤60ms · 온보드 ~5ms(로봇 측) · G01 로컬 ≤20ms |
| G4 | 핸드헬드 직결 조종 (G01 동글) | 입력→적용 p95 ≤40ms |
| G5 | 엔지니어링 뷰포트 — 화면별 환경 + 공학 오버레이 | 프리셋 5종 + CoM/FSR/IMU 오버레이 |
| G6 | 디지털 트윈 정합 — 화면=게이지=실모터 | TEL2 30Hz 위상·래치값 동기 |

## 3. 범위 / 비범위

- **범위**: Mac 전송 계층(W1), 로봇 브로커리지 v2(O0–O4), bus 직결 50Hz(D0–D3),
  핸드헬드(H0–H3), 3D 뷰포트(W2–W5). 상세 = `docs/design/README.md`.
- **비범위**: 커스텀 게이트 엔진(프리뷰 제어/capture point — "스펙 초과" 영역, 별도 결정),
  ROS 미들웨어 도입(방법론만 차용), CM-730/740 펌웨어 개조(버스 증속 등), Track C(G01 을
  네트워크 가젯으로).

## 4. 성공 지표 (프로그램 SLO 발췌 — 합격기준 상세는 03 문서)

- 온보드: 명령 실효율 4–8Hz → **≥20Hz**, E-STOP 로봇 측 100ms → **~5ms**, 통신 두절 시
  **0.6s 제자리 → 2.5s 정지** 티어 동작.
- bus 직결: 입력→서보 write **p95 ≤60ms**, 밸런스 루프 **20ms**.
- G01 동글: 입력→적용 **p95 ≤40ms**, 패드 전원 OFF 시 failsafe 즉시.
- 3D: 30fps·idle 계약 유지하면서 프리셋·오버레이 추가(회귀 0).

## 5. 제약 (전 작업 공통)

- 안전 불변식: `docs/design/README.md` §3 (E-STOP 무스로틀, 파일 폴백 영구, 거버너 로봇
  소유, 상수 단일 정의, 실기 = 크래들+토크해제+배터리 차단).
- 로봇 환경: Atom N2600 / 32-bit Ubuntu EOL / C++03 / Dynamixel 1Mbps·8ms 루프(물리 천장).
- 실기 검증이 필요한 단계는 코드 완성 후 정지하고 사용자 승인·입회 하에 진행.
