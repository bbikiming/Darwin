## 근본 원인

`DarwinForge-AppStore.entitlements` 에 **hardened runtime exception** entitlement 5개가 `<false/>` 값으로 명시되어 있었음.

```xml
<!-- 반려 유발 코드 (수정 전) -->
<key>com.apple.security.cs.allow-jit</key>
<false/>
<key>com.apple.security.cs.allow-unsigned-executable-memory</key>
<false/>
<key>com.apple.security.cs.disable-library-validation</key>
<false/>
<key>com.apple.security.cs.disable-executable-page-protection</key>
<false/>
<key>com.apple.security.cs.allow-dyld-environment-variables</key>
<false/>
```

### 왜 false 가 문제인가

이 entitlement 들은 hardened runtime 의 **예외(exception)** 를 요청하는 키다:
- `allow-jit` — JIT 컴파일 허용
- `allow-unsigned-executable-memory` — 미서명 실행 메모리 허용
- `disable-library-validation` — 라이브러리 검증 비활성
- `disable-executable-page-protection` — 실행 페이지 보호 비활성
- `allow-dyld-environment-variables` — DYLD 환경변수 허용

이들은 **"보안을 약화시키는 예외"** 이므로:
- **`true`** = 예외 활성 (앱이 해당 위험 동작 필요) → App Review 가 정당성 심사
- **부재(absent)** = 예외 없음 = **가장 안전** (모든 예외 차단)
- **`false`** = ❌ **invalid** — Apple 자동 검사가 거부

핵심: "예외를 끈다(차단한다)" 는 의도는 **명시적 false 가 아니라 키를 아예 제거** 함으로써 표현해야 한다. false 로 명시하는 것은 "값이 invalid" 로 간주된다 (QA1773).

원래 코드의 주석은 "JIT/unsigned-memory 모두 차단" 이라고 의도를 정확히 적었으나, 구현 방법(false 명시)이 Apple 규칙과 어긋났다.

### hardened runtime 영향 없음

hardened runtime 자체는 `codesign` 의 runtime option (`archive-app.sh` Step 2) 으로 활성 유지.
exception entitlement 부재 = **모든 예외 차단** = 가장 강한 보안 자세.

DarwinForge 는 표준 Swift / AppKit / Speech / Network 만 사용 — JIT / unsigned memory
예외가 전혀 필요 없으므로 키 제거가 정확한 조치.
